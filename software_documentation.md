# PCOSight Software Documentation

## 1. Overview

PCOSight is research and educational decision-support software for PCOS risk screening. The system provides a web interface where users can enter clinical, lifestyle, hormonal, and biochemical parameters to receive a PCOS risk estimate generated by saved machine learning models.

The application also includes Groq-powered auxiliary features for recommendation text and educational chat support. These LLM-assisted features are intentionally separated from the scientifically evaluated risk-estimation models. The machine learning inference pipeline produces the PCOS risk probability; the Groq components help explain, summarize, and educate after or around the screening workflow.

PCOSight should be described as:

- risk-screening software
- decision-support software
- research/educational software
- PCOS risk-estimation software

PCOSight should not be described as a diagnostic system.

## 2. Purpose And Scope

The purpose of PCOSight is to make PCOS risk screening more accessible as a software artifact derived from academic experimentation. It combines trained model artifacts, a Flask-based interface, user authentication, saved prediction records, and educational support components.

The software is intended for:

- demonstrating reproducible PCOS risk-estimation workflows
- supporting research and educational exploration of PCOS screening indicators
- providing a usable interface around saved machine learning inference models
- helping users understand screening outputs in non-diagnostic language

The software is not intended for:

- medical diagnosis
- treatment planning
- replacing clinician review
- emergency medical triage
- autonomous clinical decision-making

## 3. Medical And Safety Disclaimer

PCOSight is not a medical device and does not diagnose PCOS. It provides risk estimates for educational and research decision-support purposes only.

PCOS is a clinical condition that requires professional evaluation. Diagnosis may involve medical history, physical examination, laboratory tests, imaging, exclusion of other endocrine conditions, and clinician judgment. PCOSight does not replace any of these steps.

Users should consult a qualified healthcare professional for:

- persistent menstrual irregularity
- abnormal bleeding
- severe pain
- infertility concerns
- abnormal hormone or glucose markers
- high-risk screening results
- medication or treatment decisions

The Groq-generated recommendations and CareChat responses are educational assistance only. They must not be interpreted as medical advice, diagnosis, prescription, or treatment instruction.

## 4. Research Provenance

PCOSight originates from academic research and experimentation focused on PCOS risk screening using clinical, lifestyle, hormonal, and biochemical indicators. The project includes research notebooks and dataset resources in the `Experiments/` directory:

- `Experiments/PCOS_Dataset.csv`
- `Experiments/PCOS_Risk_Prediction.ipynb`
- `Experiments/PCOS_Risk_Prediction_Inference.ipynb`

These resources represent the experimentation and methodology foundation for the software. The web application itself is a distinct software artifact that operationalizes selected trained models through a user-facing interface.

An Open Source Paper or software-oriented publication about PCOSight should focus on the software artifact, including its architecture, implementation, inference workflow, model integration, testing, usability, and reproducibility. It should not reproduce thesis chapters as-is. Work originating in an academic thesis is not automatically treated as prior journal publication by Elsevier, but the software publication should still clearly distinguish itself as a software artifact publication.

## 5. System Architecture

PCOSight follows a lightweight Flask architecture:

```text
User Browser
    |
    v
Flask Routes in app.py
    |
    +--> Authentication and session handling
    +--> Basic prediction workflow
    +--> Advanced prediction workflow
    +--> Recommendation generation
    +--> CareChat API
    |
    v
SQLite Database through Flask-SQLAlchemy
    |
    v
Saved user prediction records
```

The machine learning inference flow is separate:

```text
User form input
    |
    v
Input parsing and feature mapping
    |
    v
Saved feature list from saved_models/
    |
    v
Saved scaler/model artifacts
    |
    v
Risk probability
```

The LLM assistance flow is auxiliary:

```text
Risk probability + input summary
    |
    v
Groq recommendation prompt
    |
    v
Educational recommendation JSON
```

CareChat is also auxiliary:

```text
User educational question
    |
    v
Groq chat completion
    |
    v
Short PCOS/reproductive-health educational response
```

## 7. Prediction Workflows

### 7.1 Basic Risk Screening

Route:

- `/basic`

Prediction function:

- `predict_basic(input_data)`

Asset loader:

- `load_basic_assets()`

Saved assets:

- `saved_models/basic_lr_model.pkl`
- `saved_models/basic_lr_scaler.pkl`
- `saved_models/basic_lr_features.pkl`

Input features:

- Age
- BMI
- cycle regularity
- pimples
- hair growth
- hair loss
- weight gain
- skin darkening
- fast food intake
- regular exercise

Workflow:

1. A logged-in user submits the basic prediction form.
2. Flask converts form values into the expected feature names and numeric types.
3. The saved feature list defines the exact model input order.
4. The basic scaler transforms the input data.
5. The basic logistic regression model returns a PCOS risk probability.
6. The result is saved for the user.
7. Groq may generate educational recommendations based on the result and inputs.

### 7.2 Advanced Risk Estimation

Route:

- `/advanced`

Prediction function:

- `predict_advanced(input_data)`

Asset loader:

- `load_advanced_assets()`

Saved assets:

- `saved_models/advanced_rf_model.pkl`
- `saved_models/advanced_rf_features.pkl`

Input features:

- Age
- BMI
- cycle regularity
- pimples
- hair growth
- hair loss
- weight gain
- skin darkening
- AMH
- LH
- FSH
- LH/FSH ratio
- TSH
- PRL
- RBS

Workflow:

1. A logged-in user submits the advanced prediction form.
2. Flask converts form values into model-ready feature names and numeric values.
3. The saved advanced feature list defines the exact input order.
4. The random forest model returns a PCOS risk probability.
5. The result is saved for the user.
6. Groq may generate educational recommendation text after prediction.

## 8. Separation Of Research Inference And LLM Assistance

PCOSight contains two different AI-related layers. They should not be merged conceptually.

### 8.1 Scientifically Evaluated Risk Inference

The PCOS risk-estimation algorithm is the saved machine learning model pipeline. It uses structured numerical inputs and serialized model assets from `saved_models/`.

This layer is responsible for:

- feature ordering
- preprocessing
- model inference
- probability generation
- reproducible risk estimation

This is the component connected to the research experimentation and model evaluation.

### 8.2 Groq LLM Assistance

Groq is used for:

- generating short educational recommendations after prediction
- powering PCOS CareChat for general educational questions

This layer is responsible for:

- natural-language explanation
- educational support
- user-friendly recommendation formatting
- general PCOS awareness conversation

This layer is not responsible for generating the validated risk probability. It should be described as auxiliary interpretation and education support, not as the risk-prediction algorithm.

## 9. Authentication And Data Persistence

PCOSight uses Flask sessions for authenticated access. Users can register, log in, view a dashboard, submit prediction forms, and return to previously saved prediction results.

Password handling uses Werkzeug password hashing.

The SQLite database stores:

- user email
- username
- password hash
- prediction type
- prediction probability
- submitted input data
- generated recommendation data
- created and updated timestamps

The application stores only the latest result for each user and prediction type because `PredictionResult` enforces a unique constraint on `(user_id, prediction_type)`.

## 10. Environment Configuration

Required environment variables:

```env
SECRET_KEY=your-secret-key
GROQ_API_KEY=your-groq-api-key
GROQ_MODEL=llama-3.3-70b-versatile
CHATBOT_MODEL=llama-3.3-70b-versatile
```

Notes:

- `SECRET_KEY` secures Flask sessions.
- `GROQ_API_KEY` is required for Groq recommendation and CareChat functionality.
- `GROQ_MODEL` controls recommendation generation.
- `CHATBOT_MODEL` controls CareChat responses.
- The machine learning prediction functions use local saved model files and are conceptually independent from Groq.

## 13. Error Handling And Fallbacks

The recommendation generator includes a fallback response if the Groq API request fails. This ensures that the prediction workflow can still complete even when the auxiliary recommendation service is unavailable.

For prediction functions, missing expected model features raise errors rather than producing silent or misleading predictions. This is important because feature order and feature completeness are essential for reproducible machine learning inference.

## 14. Known Limitations

- PCOSight is not a clinical diagnostic tool.
- Prediction quality depends on the dataset, feature engineering, and model evaluation from the underlying research workflow.
- Saved model artifacts may be sensitive to library version compatibility.
- Groq-generated educational content may vary between runs.
- The application currently uses SQLite, which is suitable for local or lightweight deployment but not ideal for high-scale production use without modification.
- The system does not replace clinician interpretation of laboratory markers or symptoms.

## 15. Ethical And Responsible Use

PCOSight should be used with careful language and appropriate boundaries. Outputs should be framed as risk estimates, screening support, or educational decision-support. Users should not be told that the software has diagnosed them.

Recommended terminology:

- "risk screening"
- "risk estimation"
- "decision-support"
- "educational support"
- "research software"
- "screening result"

Terms to avoid:

- "diagnosis"
- "definitive detection"
- "confirmed PCOS"
- "medical decision"
- "treatment recommendation"

## 16. Maintenance Notes

When updating the software:

- keep feature names aligned with the saved model feature files
- update tests if routes, form fields, or model assets change
- keep Groq prompts non-diagnostic and educational
- document any new saved model artifact and its intended inference route
- rerun the automated tests before release or publication
- preserve the distinction between research inference and LLM assistance
